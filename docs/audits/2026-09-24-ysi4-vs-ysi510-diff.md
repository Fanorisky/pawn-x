## 2. Library Inventory Diff

### 2.1 Top-level directories

**Added in NEW:** `amx/`, `code-parse/`, `indirection/`, `md-sort/` (git submodules, now vendored/checked out), `.github/`.
**Removed in NEW:** `YSI_Internal/` (dissolved, see below).

Top-level markdown docs are **new**: `readme.md`, `installation.md`, `troubleshooting.md`, `YSI_COMPATIBILTY_MODE.md`, `annotations.md`. OLD had **0** `.md` files; NEW ships **463** (per-library `api.md`/`features.md`/`faqs.md`/`quick-start.md`/`internal.md`).

| `y_version.inc`, `y_pp.inc`, `y_compilerdata*`, `y_globaltags.inc`, `y_determine_os.inc`, `y_shortfunc.inc` | `YSI_Core/y_core/` (+ `YSI_Core/y_compilerdata.inc`) |

Net effect: nothing user-facing was "lost". The internal plumbing was reorganized into `YSI_Core/y_core/` and the three new submodules.

### 2.3 The four submodules

- **`amx/`** (Zeex/amx_assembly) was already a declared submodule in OLD's `.gitmodules` but **not checked out** in the OLD snapshot; now vendored. Low-level AMX/assembly toolkit: `addressof*`, `dynamic_call`, `codescan`, `asm_macros`, `frame_info`, `heap_alloc`, `phys_memory`, JIT support. **Provides capability that OLD open-coded** in `YSI_Internal/y_writemem`, `y_renative`, etc.
- **`code-parse/`** (Y-Less/code-parse.inc): **new**. Compile-time parser of function signatures/parameter lists. Auto-generates `CallRemoteFunction` specifier strings, counts/typing of params. This underpins the rewritten `y_hooks` (function/native hooking), `y_timers`, and remote calls.
- **`indirection/`** (Y-Less/indirection): **new**. Type-safe function-pointer calling: `@.func(...)` with `Func:f<iisi>` tag-encoded signatures. One common interface replacing `CallLocalFunction`/`Callback_Call`/`defer`. Underpins hooks, `y_inline`, `y_remote`, `defer`.
- **`md-sort/`** (oscar-broman/md-sort): **new**. Multi-dimensional array sorting (`SortDeepArray`, `SORT_DESC`). Powers the new `y_sortedarray`.

`code-parse` + `indirection` + `amx/addressof` together are the machinery that makes NEW's function/native hooking and the "annotations" syntax possible.

## 3. Changes in the pawn-x-relevant libraries

### 3.1 Iteration / `foreach` / `iterfunc` / `yield` (`YSI_Data/y_foreach*`, `y_iterate*`)

**File layout (renames only):**
`y_foreach/yield.inc` → `y_foreach/y_foreach_yield.inc`; `impl/iterators/macros/tests/warning.inc` → `y_foreach_impl.inc` etc.; added `y_foreach_entry.inc` (entry point) and doc files (`yield.md`, `features.md`, `api.md`, `faqs.md`, `quick-start.md`, `internal.md`).

**Include mechanism changed:** `y_iterate.inc` / `y_foreach.inc` are now thin wrappers that `#tryinclude` `…/y_foreach/y_foreach_entry` through a chain of fallback paths (`y_foreach\…`, `YSI_Data\…`, `<YSI\YSI_Data\…>`). Entry-point indirection is new.

**`yield` implementation, same algorithm, refactored:** (OLD `yield.inc` 333 lines → NEW 444).
- Core mechanism unchanged: `E_ITER_YIELD` state struct, `Iter_YieldEnter` / `Iter_YieldLoop` / `Iter_YieldReturn`, the `iteryield` macro, `MAX_NESTED_ITERATORS` (4), `MAX_YIELD_MEMORY` (512), the "`2N+1` calls" stack-copy trick, and the `#emit` stack/heap save-restore are byte-for-byte equivalent in logic.
- **Magic `#emit` numbers replaced with named constants**: `FILL 44`→`FILL __11_cells`, `SCTRL 4/2/5/6`→`SCTRL __stk/__hea/__frm/__cip`, `ADD.C 12`→`ADD.C __3_cells`, `-1`→`__minus1`, etc.
- **JIT compatibility added:** the jump-back sequences now emit `SCTRL __jit_jump` *before* `SCTRL __cip` (both in `Iter_YieldLoop` and `Iter_YieldReturn`). OLD only did the raw `SCTRL 6` (CIP). This is the meaningful behavioral change: yield now cooperates with the JIT plugin.
- **`yield` is now a gated keyword.** OLD: `#define yield%0…` unconditionally, plus `yieldreturn`/`yieldbreak`. NEW: `#define YIELD__…` always defined, and `yield`→`YIELD__` only `#if YSI_KEYWORD(yield)` (so it can be disabled / used as `YIELD__` in compatibility mode). `yieldreturn`→`YIELD__return`, `yieldbreak`→`YIELD__break`.
- Init moved from `hook public OnScriptInit()` to a chained **`public OnCodeInit()`** hook (new lifecycle callback used in 33 places across NEW).
- `P:E(...)` error → `Debug_Error(...)`. Added empty stub `Iter_NewYield()`.

**Iterator / special-iterator API, source-compatible, extended:**
- `iterfunc`, `iterstart@X`, `Iterator@X`, `iteryield`, `iterstate(...)` conventions are **preserved** (writing custom iterfuncs works the same; `#define iterstart@Foo iteryield` still the way to opt into yield). NEW also accepts `Iterator@X iteryield` form.
- **New public `Iter_*` macros (none removed):** `Iter_Available`, `Iter_Debug`, `Iter_Excludes`, `Iter_InitAndClear`, `Iter_IsEmpty`, `Iter_IsFull`, `Iter_NonEmpty`, `Iter_NonFull`, `Iter_Tag`, `Iter_Yield`. All the OLD ones (`Iter_Add/Remove/Free/Contains/Count/Clear/Alloc/Random*/Begin/End/SafeRemove/GetMulti/FreeMulti/FastClear`) remain.
- **New built-in iterators:** `N(cur, n)` and yield-based `VehicleOccupant`, `VehiclePassenger`, `VehicleDriver`. `Null`/`NonNull`/`Until`/`Filter` now take `const arr[]`.

### 3.2 Varargs (`YSI_Coding/y_va*`)

Layout: `y_va/impl.inc`+`tests.inc` → `y_va_entry/header/impl/tests.inc` + docs.

- **`___(n)` was already the primary syntax in OLD** (three-dots-to-take, three-underscores-to-pass); it is *not* new to this bump. So pawn-x's `___` mirror still lines up.
- **New in NEW:** shorthand `___0`…`___9` (= `___(0)`…`___(9)`); `va_args<>`/`va_start<>` are now formally defined as aliases (`va_args<%0> → GLOBAL_TAG_TYPES:...`, `va_start<%0> → ___(%0)`).
- **`GLOBAL_TAG_TYPES` / `CUSTOM_TAG_TYPES`:** variadic params accept a *set* of tags (`{_,Language,Bit,Text,Menu,Style,XML,Bintree,Group,Timer,File,Float,Text3D,…}`), extensible via `#define CUSTOM_TAG_TYPES …`.
- **Auto-extended stdlib functions:** ~30 native/library functions (`SendClientMessage`, `TextDrawSetString`, `ShowPlayerDialog`, `CreateMenu`, `DBQuery`, `Create3DTextLabel`, `SetObjectMaterialText`, `AddServerRule`, …) are transparently given formatting varargs. Opt out with `#define YSI_NO_AUTO_VA` and use the `va_`-prefixed variants; these short-circuit `format` when no args.

### 3.3 Hooks (`YSI_Coding/y_hooks*`)

Full rewrite. `impl.inc` 1209 → `y_hooks_impl.inc` **2501** lines; `macros.inc` 125 → 414.

- **Function / native / stock hooking is the headline new capability.** OLD `hook` only wrapped callbacks/publics (`#define hook%1(%2) forward UNIQUE_FUNCTION<…>`). NEW adds `hook function`, `hook native`, `hook public`, `hook stock` (macros `HOOK_function__`/`HOOK_native__`/`HOOK_public__`/`HOOK_stock__`), implemented via `ADDRESSOF_MAKE_CALL__` + the `amx/addressof`, `code-parse`, and `indirection` submodules.
- **Explicit chaining via `continue`:** function hooks call the next in the chain with `continue`, giving pre/post-processing and full control of ordering; hooks can return *any* value (not just 0/1).
- **`DEFINE_HOOK_RETURN__(Callback, value)`**: new; sets a callback's default chain return (e.g. `OnPlayerCommandText`→0). This is directly the HOOK_RET area.
- **`~0` / `~1` early-return semantics:** returning `~0`/`~1` from a hook halts the chain immediately and returns that value. (Replaces the OLD verbose return-mask macros.)
- **`DEFINE_HOOK_REPLACEMENT__`** (CamelCase-aware short-form names, e.g. `Inventory`→`Inv`): OLD had `DEFINE_HOOK_REPLACEMENT` (single-underscore); NEW is `__`-suffixed.
- **Compatibility-mode macros:** `HOOK__`, `REHOOK__`, `HOOK_RETURN__`, all gated on `YSI_KEYWORD(hook)` etc. New param-scanning macro families `YHLEG_*` (legacy/signature) and `YHNPS_*` (native param scan).
- **Removed OLD macros:** `CHAIN_ORDER`, `HOOK_FORWARD`, `PRE_HOOK`, `@yH_native` (superseded by the new chaining model).

## 4. Notable New Features / Removals Elsewhere

- **`YSI_COMPATIBILITY_MODE`** (`YSI_COMPATIBILTY_MODE.md`): a global build flag (`#define YSI_COMPATIBILITY_MODE` at top of script, or `=1` on cmdline) that disables *all* of YSI's custom keywords (`timer`, `hook`, `yield`, `foreach`, …) and replaces them with uppercase double-underscore forms (`TIMER__`, `HOOK__`, `YIELD__`, `DEFER__`). Motivation: keyword collisions with other libs (pawn-plus also has `yield`; multiple `foreach` implementations exist). Individual keywords can be re-enabled (`#define YSI_KEYWORD_hook`) or individually disabled (`#define YSI_NO_KEYWORD_hook`). **This is the mechanism gating `yield`/`hook`/`foreach`, directly relevant to pawn-x, which reimplements those keywords natively and could collide.**
- **Annotations / decorators** (`annotations.md`, new `y_decorator.inc`): a more consistent syntax layer over `hook`, `hook native`, `TEST__`, `YCMD`, `timer`, `foreign`/`global`, `PROFILE__`.
- **`installation.md`**: sampctl-based install (`sampctl package install pawn-lang/YSI-Includes@5.x`); compile-time quieting defines `YSI_NO_CACHE_MESSAGE`, `YSI_NO_OPTIMISATION_MESSAGE`, `YSI_NO_VERSION_CHECK`, `YSI_NO_MASTER`.
- **`troubleshooting.md`**: points to per-library FAQ docs, forums, discord, github issues.
- New libraries of note: `y_async` (async/await over callbacks), `y_ctrl`, `y_ebc`, `y_scriptdata`/`y_serverdata`, `y_bcrypt` (+ `y_inline_bcrypt`), `y_sortedarray`/`y_sparsearray`/`y_circular`/`y_percent`, `y_weapondata`, and the `y_inline_*` plugin adaptors.

## 5. Build / Structural Impact for Scripts Using the New YSI

1. **New required submodules.** Building NEW needs `amx`, `code-parse`, `indirection`, `md-sort` present (clone `--recurse-submodules` or via sampctl). Missing `code-parse`/`indirection` breaks the new `y_hooks` and remote/inline machinery.
2. **The flat `<YSI\…>` include directory is gone / deprecated.** OLD had `YSI/y_hooks.inc`, `YSI/y_va.inc`, etc. (a flat compat include dir). NEW replaces it with placeholder files literally spelling **"DO NOT USE YSI DIRECTORY IN YOUR INCLUDES INSTEAD USE MORE SPECIFIC ONES LIKE - YSI_Data"**. Scripts must include by group: `#include <YSI_Coding\y_va>`, `<YSI_Coding\y_hooks>`, `<YSI_Data\y_iterate>` (or `y_foreach`), etc. `#include <YSI_Group\y_library>` pulls everything.
3. **Entry-point indirection.** Each `y_X.inc` now `#tryinclude`s `y_X/y_X_entry.inc` via a path-fallback chain, so include paths must let the compiler resolve the nested `*_entry.inc` files.
4. **New `OnCodeInit` lifecycle callback** is chained by many libraries (33 sites), including yield init. Scripts hooking startup should be aware it exists alongside `OnScriptInit`.
5. **Keyword-collision surface.** Because NEW gates `yield`/`hook`/`foreach`/`timer` behind `YSI_KEYWORD(...)` and offers `YSI_COMPATIBILITY_MODE`, a compiler like pawn-x that provides these natively can coexist by having the script enable compatibility mode (or disable the specific YSI keyword), letting YSI fall back to `YIELD__`/`HOOK__` forms.

## Summary of pawn-x-mirrored areas

| Area | OLD → NEW verdict |
|---|---|
| **`___` varargs** | Same syntax; NEW adds `___0..___9`, formalized `va_args<>`/`va_start<>` aliases, `GLOBAL_TAG_TYPES`. No breaking change. |
| **`foreach`/iterators** | Source-compatible; +10 new `Iter_*` macros, new built-in iterators, entry-point/include restructure. |
| **`iterfunc`/generators/`yield`** | Same algorithm; JIT-compat jump added (`SCTRL __jit_jump`), named constants, `yield` now a gated keyword (`YSI_KEYWORD`), init via `OnCodeInit`. |
| **`hook`** | Major upgrade: function/native/stock hooking via addressof+code-parse+indirection, `continue` chaining, `DEFINE_HOOK_RETURN__`, `~0`/`~1` immediate returns (HOOK_RET), compat `HOOK__`/`REHOOK__`. |
